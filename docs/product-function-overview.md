# QnAI Studio 产品功能说明

## 1. 产品定位

QnAI Studio 是一款桌面端 AI 编程工作台，面向需要在本地项目中与多种 AI 编程引擎协同工作的开发者。
它提供统一的对话入口、工作区管理、文件浏览、代码编辑、工具调用展示和会话历史能力，用来降低不同 AI CLI 工具之间的切换成本。

它的核心价值不是替代某一个单独的模型，而是把多个 AI 编程引擎整合进同一套本地开发工作流中。

## 2. 目标用户

主要面向以下几类用户：

- 使用 Claude Code、Codex CLI、Gemini CLI、IFlow 等工具的开发者
- 需要在本地代码仓库中进行 AI 辅助编程的工程团队
- 需要跨多个项目目录进行代码审查、重构、解释和修改的用户
- 希望保留本地工作区控制权，而不是完全依赖云端 IDE 的用户

## 3. 核心能力概览

产品当前提供以下核心能力：

1. 多引擎统一接入
2. 多工作区管理
3. 跨工作区文件引用
4. AI 对话与流式输出
5. 工具调用可视化
6. 会话历史与恢复
7. 本地文件浏览与编辑
8. 工作区版本快照
9. 配置中心与引擎管理
10. 悬浮窗与主题切换
11. 日志、状态与开发者调试支持

## 4. 功能模块说明

### 4.1 多引擎统一接入

系统支持多个 CLI 型 AI 引擎接入，并在统一界面中切换使用。

当前已支持的引擎包括：

- Claude Code
- Codex CLI
- Gemini CLI
- IFlow

#### 用户价值

- 不需要分别打开多个独立 CLI 工具
- 可以在同一工作区中切换不同引擎完成不同任务
- 统一使用同一套会话、文件、上下文和工具展示界面

#### 典型场景

- 用一个引擎做代码解释，另一个引擎做改写建议
- 在同一个项目里对比不同引擎的结果
- 根据团队现有账号体系选择不同 provider

### 4.2 工作区管理

系统以“工作区”为基本操作边界。
用户可以把一个或多个本地项目目录注册为工作区，并在这些工作区之间切换。

#### 支持的工作区概念

- 当前工作区：AI 当前主要执行与写入的目录
- 关联/上下文工作区：AI 可以同时读取的其他项目目录，用于跨项目分析与引用
- 查看工作区：文件浏览器当前正在查看的目录，不一定等于当前执行工作区

#### 用户价值

- 保持 AI 操作的项目边界清晰
- 支持多仓库联动分析
- 避免误把修改写入错误目录

#### 典型场景

- 主项目在 `frontend`，同时引用 `shared-utils`
- 只查看某个工作区文件，但仍让 AI 在另一个工作区执行写入
- 切换不同客户项目时保留各自独立上下文

### 4.3 文件引用能力

用户可以在聊天输入中通过文件引用语法把工作区文件纳入上下文。

#### 支持方式

- 当前工作区文件引用
- 跨工作区文件引用
- 多文件联合引用

#### 用户价值

- 不需要手工复制大段代码到聊天框
- 能明确指定 AI 应该读取哪些文件
- 更适合做代码解释、对比、审查和重构任务

### 4.4 AI 对话与流式输出

系统提供统一的对话界面与消息流展示能力。
AI 输出不是一次性整段返回，而是流式逐步生成。

#### 交互特征

- 用户发送消息后可实时看到输出增长
- 支持中断当前会话
- 支持继续会话
- 支持重新生成
- 支持消息归档与展示压缩

#### 用户价值

- 降低等待不确定感
- 更适合长回答和工具调用型任务
- 保留连续对话上下文，而不是每次重新开始

### 4.5 工具调用可视化

当 AI 使用工具时，系统会将工具调用过程和输出展示在消息流中，而不是隐藏在后台。

#### 可展示内容

- 工具调用块
- 工具执行状态
- 工具返回输出
- 工具相关日志/调试信息

#### 用户价值

- 提高 AI 行为透明度
- 用户可以判断 AI 读了什么、做了什么
- 对审查、调试和问题定位更友好

### 4.6 会话历史与恢复

系统支持聊天会话的本地保存、历史浏览和恢复。

#### 支持能力

- 自动保存当前会话状态
- 应用重启后恢复历史对话
- 查看历史会话
- 删除历史会话
- 消息归档与压缩展示

### 4.7 本地文件浏览与代码编辑

系统内置文件浏览器与代码编辑器，允许用户在同一界面内查看和编辑工作区文件。

#### 文件浏览能力

- 浏览目录树
- 搜索文件
- 读取文件内容
- 创建文件/目录
- 删除或重命名文件

#### 编辑能力

- 打开文件编辑
- 多文件切换
- 结合 AI 对话进行修改
- 使用 CodeMirror 提供编辑体验

### 4.8 工作区版本快照

系统提供工作区版本/快照机制，用于在 AI 操作前后保存状态并支持恢复。

#### 主要用途

- 在较大改动前建立保护点
- 回滚 AI 引入的错误修改
- 管理某一阶段的重要工作区状态

### 4.9 配置中心与引擎管理

系统提供设置页用于统一管理引擎、provider 和应用行为。

#### 可配置项

- 默认引擎
- 各 CLI 路径
- provider 信息
- 模型参数
- base URL
- 悬浮窗参数
- 主题与界面设置
- 工作目录相关信息

### 4.10 悬浮窗与主题切换

系统支持主窗口之外的悬浮窗模式，以及浅色/深色主题切换。

### 4.11 状态栏、日志与开发者面板

产品不仅提供普通用户功能，也包含面向调试和开发态的可观测能力。

#### 状态栏

展示当前引擎状态、连接状态、错误信息和全局运行反馈。

#### 日志能力

支持查看和清理日志，便于排查问题。

#### 开发者面板

可观察事件流、工具调用过程和调试信息。

### 4.12 上下文管理能力

系统不仅依赖用户手输 prompt，也在逐步建立结构化上下文管理能力。

#### 可纳入的上下文类型

- 项目文件
- 文件结构
- 用户选区
- IDE 诊断信息
- 历史上下文
- 语义相关内容

## 5. 典型使用流程

### 场景一：新项目接入

1. 用户创建或导入工作区
2. 在设置中配置 CLI 路径和默认引擎
3. 系统进行健康检查
4. 用户开始在聊天窗口提问并引用文件

### 场景二：跨项目分析

1. 选择一个当前工作区
2. 添加一个或多个关联工作区
3. 在消息中引用不同工作区文件
4. AI 基于多项目上下文给出分析结果

### 场景三：AI 辅助改代码

1. 用户浏览文件并打开编辑器
2. 在聊天中要求 AI 分析或修改某段逻辑
3. 观察工具调用和输出过程
4. 在编辑器中检查或补充修改
5. 需要时创建工作区快照或恢复版本

### 场景四：恢复历史工作

1. 重新打开应用
2. 系统恢复上次会话状态
3. 用户查看历史会话或直接继续当前会话
4. 保留原有上下文继续开发

## 6. 当前产品特征总结

从产品能力上看，QnAI Studio 当前不是一个单纯“聊天机器人桌面壳”，而是一个更接近 AI IDE 工作台的本地应用，具备以下特征：

- 多引擎统一入口
- 多工作区组织能力
- 本地文件与编辑闭环
- 工具调用过程可见
- 会话历史可恢复
- 工作区状态可快照
- 面向 AI IDE 场景的上下文结构基础

## 7. 当前版本边界

基于现有实现，当前产品更适合：

- 本地代码理解
- 辅助重构
- 跨项目审查
- CLI agent 统一调度
- 本地文件级 AI 协作

它暂时不以以下方向为主要重点：

- 云端团队协作
- 复杂在线同步
- 完整 Git 平台替代
- 大规模项目管理平台能力

## 8. 一句话产品总结

QnAI Studio 是一款面向本地开发场景的多引擎 AI 编程工作台，用统一桌面界面把 AI 对话、工作区、文件、编辑、工具调用和会话管理整合到同一条开发链路中。
