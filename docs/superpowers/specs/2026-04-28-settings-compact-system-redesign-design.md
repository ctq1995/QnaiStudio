# 设置界面紧凑系统风重构设计

## 背景
当前设置界面经过多轮样式调整后，仍存在三个核心问题：
1. 主界面结构不够稳定，视觉语言在“主题面板”和“系统设置”之间摇摆。
2. 局部样式虽然已经做过去透明处理，但整体布局仍不够紧凑，缺少真正的系统设置中心秩序。
3. 现有设置窗口与内容分组仍偏向组件堆叠，而不是面向桌面应用的设置工作流。

用户新要求是：重新设计并按方案 A 实现，目标为“紧凑系统设置风”，参考系统设置类案例，对设置界面进行整体布局重构，而不是继续在现有视觉上做局部修补。

## 目标

### 视觉目标
1. 设置窗口明确呈现为一张白色设置面板，与外层遮罩清晰分离。
2. 整体风格参考系统设置中心，强调秩序、稳定、紧凑，而不是展示感。
3. 信息密度高于当前版本，但保持良好的可读性和扫描效率。
4. 所有设置子页共享统一布局规则、边框规则、间距规则和状态表达规则。

### 交互目标
1. 保留左侧分类导航 + 右侧内容详情的主交互模式。
2. 保留当前设置分类，不更改信息架构。
3. 保留现有编辑、保存、未保存拦截、关闭确认等逻辑。
4. 提升从“打开设置”到“定位分类、编辑、保存”的效率。

### 范围
本次只重构设置界面布局与表现层，不调整配置结构和业务保存逻辑。涉及文件：
- [SettingsModal.tsx](src/components/Settings/SettingsModal.tsx)
- [SettingsContent.tsx](src/components/Settings/SettingsContent.tsx)
- [EngineSettingsPanel.tsx](src/components/Settings/EngineSettingsPanel.tsx)
- [ProvidersSettingsPanel.tsx](src/components/Settings/ProvidersSettingsPanel.tsx)
- [FloatingWindowSettingsPanel.tsx](src/components/Settings/FloatingWindowSettingsPanel.tsx)
- [AboutSettingsPanel.tsx](src/components/Settings/AboutSettingsPanel.tsx)
- 以及必要的通用设置组件：[SettingsCardOption.tsx](src/components/Settings/SettingsCardOption.tsx)、[SettingsToggle.tsx](src/components/Settings/SettingsToggle.tsx)、[DirtyBadge.tsx](src/components/Settings/DirtyBadge.tsx)

不包含：
- 新增设置分类
- 修改配置字段
- 修改保存 API
- 改造设置以外的全局 UI

## 方案选择

### 方案 A：紧凑系统设置页（采用）
参考方向：
- macOS System Settings 的结构秩序
- Windows 11 Settings 的稳定分栏

核心特征：
- 左侧窄栏分类导航
- 右侧紧凑内容区
- 纯白主面板 + 浅灰导航栏 + 细边框分组
- 内容以“设置组”组织，而不是大卡片堆叠

选择原因：
- 与用户要求的“紧凑一点、布局完全重构”最一致。
- 能兼容当前复杂表单项，如路径、模型、API Key、连接测试。
- 比仪表盘风格更稳，也比列表-详情二级结构更适合当前四个固定分类。

## 信息架构
设置分类保持不变：
- 引擎设置
- 模型服务商
- 悬浮窗
- 关于

原因：当前问题主要在布局和视觉，不在分类结构。

## 布局设计

### 外层模态
- 使用深色半透明遮罩，负责模态语义。
- 设置主窗固定居中，尺寸参考桌面应用设置窗。
- 主窗必须始终为明确纯白色，不跟随主题背景混色。

### 主窗结构
主窗拆为两栏：
- 左侧导航栏：约 196–208px
- 右侧内容区：剩余全部空间

整体尺寸原则：
- 高度约为视口的 80–86%
- 最大宽度控制在 1100–1180px
- 圆角收敛到中等尺寸，不做夸张圆角
- 只保留外层窗口阴影，内部尽量不使用阴影

### 左侧导航栏
结构分三段：
1. 顶部标题区
2. 分类列表区
3. 底部辅助说明区

要求：
- 背景为极浅灰，不用纯白，以便与右侧内容区区分。
- 分类按钮为紧凑列表项，高度统一。
- 激活态使用浅灰底 + 深色文字 + 左侧细强调条。
- 图标缩小，只做辅助识别。
- 导航项默认只显示分类名，不展示长描述。

### 右侧内容区
结构分三段：
1. 顶部标题栏
2. 中部滚动内容区
3. 底部固定保存栏

#### 顶部标题栏
- 显示当前分类标题和一句简短描述。
- 标题区高度收紧，不再使用大标题 hero 风格。
- 右上角仅保留关闭按钮。
- 未保存状态使用小标签贴近标题展示。

#### 中部滚动内容区
- 以设置组为基本单位。
- 每个设置组采用统一白底 + 浅灰边框。
- 每组内部为：标题、说明、控件内容。
- 默认单列，短字段可以双列。
- 长字段如路径、URL、API Key、模型输入保持全宽。

#### 底部保存栏
- 固定于底部，不随内容滚动。
- 左侧显示状态文案。
- 右侧显示关闭和保存按钮。
- 样式比顶部更轻，作为操作收束区。

## 子页设计

### 引擎设置页
拆分为以下设置组：
1. 默认引擎
2. CLI 路径
3. 服务商与模型
4. 连接测试
5. 高级参数

规则：
- 不再使用“概览卡片”作为视觉重点。
- 引擎选择区域更像设置列表中的选项组。
- 参数区按功能分组，不重复渲染相同编辑器。
- 脏状态只体现在字段级标签，不单独制造横幅。

### 服务商设置页
拆分为：
1. 顶部工具区
2. 新增服务商编辑区（条件显示）
3. 服务商列表编辑区
4. 简短说明区

规则：
- 服务商卡片不是展示卡，而是可编辑设置组。
- 删除按钮为明确危险操作，但不扩大视觉权重。
- 空状态为简短说明 + 新增按钮。

### 悬浮窗设置页
拆分为：
1. 总开关组
2. 模式选择组
3. 悬停行为组
4. 自动模式延迟组（条件显示）

规则：
- 所有内容都用统一设置组样式。
- 模式选择项保持简洁，不做大面积高亮块。
- 滑块区也是普通设置组的一部分。

### 关于页
拆分为：
1. 应用信息
2. 项目来源
3. 版本信息占位（如已有可接入）

规则：
- 极简展示
- 不使用额外强调视觉
- 与其他页面保持相同分组风格

## 通用组件规则

### SettingsCardOption
- 改为更像“设置选项块”，而不是营销卡片。
- 统一中小圆角、浅边框、白底。
- 激活态只提升边框/文字层级，不做强背景渲染。

### SettingsToggle
- 改为标准系统设置行：左侧文本，右侧开关。
- 容器白底细边框。
- 行高、间距、描述字号统一。

### DirtyBadge
- 维持小型状态标签定位。
- 不扩大视觉占比。
- 用于字段级提示，不作为页面主状态组件。

## 视觉规范

### 色彩
- 主窗：纯白
- 左侧导航栏：浅灰
- 内容区：纯白
- 分组边框：浅灰
- 标题文字：深灰近黑
- 描述文字：中灰
- 主按钮：保留主色
- 危险态：实底红色，仅用于错误或删除危险动作

### 圆角与边框
- 主窗：12–16px
- 设置组：10–12px
- 输入框、按钮、导航项：8–10px
- 边框统一为浅灰细线

### 间距
- 顶部标题栏、底部操作栏高度都压缩
- 设置组之间保持 12–16px 级别间距
- 单组内部控件垂直间距保持统一
- 避免大块留白

### 阴影
- 只允许主窗使用明显阴影
- 组内禁止依赖阴影建立层级

## 数据流与行为
保持现有逻辑不变：
- 继续使用 [useSettingsEditor.ts](src/components/Settings/useSettingsEditor.ts)
- 继续使用当前脏状态判断
- 继续沿用保存和关闭确认流程
- 只改变展示形式，不改变业务规则

## 错误与状态展示
- 页面级错误使用顶部实底错误条
- 未保存状态作为标题小标签和底栏状态文案共同表达
- 保存中只体现在按钮文案和禁用状态
- 不再展示大面积成功提示块

## 验证要求

### 布局验证
1. 设置窗打开后能明显与遮罩区分，主窗必须是白底。
2. 左侧导航更窄、更紧凑。
3. 右侧标题栏、中部内容区、底部保存栏分层清晰。
4. 所有页面都遵循统一设置组样式。

### 功能验证
1. 分类切换正常
2. 所有字段仍可编辑
3. 引擎路径、模型、服务商设置正常
4. 新增/编辑/删除服务商正常
5. 悬浮窗设置正常
6. 保存、关闭、未保存拦截逻辑正常
7. 构建通过
