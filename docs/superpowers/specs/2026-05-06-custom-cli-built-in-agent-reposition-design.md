# Custom CLI 作为内置 Agent 的设置语义重定位设计

## 背景

当前 `custom-cli` 已接入前后端运行链路，但设置页与连接提示仍大量沿用“外部 CLI 引擎”模型，包括：

- CLI 路径输入
- 外部命令查找提示
- 安装/探测文案
- 连接失败覆盖层中的外部命令排查语义

这与产品目标不一致。该能力在产品定位上应被视为“内置自研 Agent”，而不是“用户自行安装并配置路径的外部 CLI”。

本次设计只做第一阶段语义重定位，不扩展新的 Agent 能力配置，不迁移底层配置结构。

## 目标

将 `custom-cli` 在设置页中的展示语义重定位为“内置 Agent”，并满足以下目标：

1. 用户仍可在引擎列表中选择 `custom-cli`
2. 选中 `custom-cli` 后，不再展示 CLI 路径输入相关 UI
3. 保留服务商与模型选择，作为内置 Agent 的核心配置入口
4. 移除或替换所有“外部 CLI 安装/查找/探测”语义
5. 不修改底层运行链路，不引入配置迁移

## 非目标

本次不包含以下内容：

- 不新增 Agent 权限开关
- 不新增运行模式配置
- 不新增自动探测或路径校验
- 不迁移 `customCli.cliPath` 配置字段
- 不重写 Rust bridge 或前端 session/parser/gateway

## 方案选择

### 方案 1：最小 UI 语义重定位（采用）

仅调整前端设置页与相关提示文案，将 `custom-cli` 视为“内置 Agent”展示；底层仍复用既有运行链路。

优点：

- 改动范围小
- 与当前产品定位一致
- 不触发配置迁移与兼容问题

缺点：

- 底层仍保留历史字段命名，如 `customCli.cliPath`
- 语义重定位主要发生在 UI 层，未同步清理底层命名

### 方案 2：UI + 配置结构重命名

暂不采用。需要处理配置迁移和兼容问题，超出当前阶段范围。

### 方案 3：完整 Agent 专属设置面板

暂不采用。需要新增能力配置模型，超出当前阶段范围。

## 设计

### 1. 引擎卡片语义

在设置页引擎列表中，`custom-cli` 应显示为内置 Agent，而不是外部 CLI。

调整方向：

- 名称改为“内置 Agent”或等价文案
- 描述改为“基于内置自研 Agent 能力运行，使用所选服务商与模型”

该改动只影响展示文案，不改变 `EngineId`。

### 2. 设置面板内容

当选中 `custom-cli` 时：

- 不再渲染路径输入区
- 不再显示“CLI 命令路径”类标题
- 保留服务商选择
- 保留模型选择

这样 `custom-cli` 的第一阶段配置能力被限定为“能力来源配置”，而不是“本地二进制配置”。

### 3. 状态校验语义

当前通用按钮文案为“测试连接”。对于 `custom-cli`，该语义偏向外部 CLI。

第一阶段调整为中性表达，例如：

- “校验状态”
- 或“验证能力”

此处只调整 `custom-cli` 的按钮文案与结果提示语义，不改变其底层调用入口；仍可复用现有 `testEngineConnection`。

### 4. 连接失败覆盖层语义

`custom-cli` 不应再显示：

- `where xxx`
- `which xxx`
- `xxx --version`
- “安装 CLI”类提示

第一阶段推荐做法：

- 保留覆盖层框架
- 将 `custom-cli` 的内容改为“内置 Agent 当前不可用”的中性提示
- 提示用户检查当前服务商、模型和运行环境，而不是外部命令路径

如果当前覆盖层结构难以局部替换，则允许对 `custom-cli` 暂时不展示该覆盖层，但优先级低于中性化替换。

### 5. 配置兼容策略

配置类型与持久化结构保持不变：

- 继续保留 `config.customCli`
- 继续保留 `customCli.cliPath`

但在 UI 第一阶段：

- 不向用户展示该字段
- 不强调其含义
- 不新增相关输入交互

这样可以避免配置迁移带来的风险。

## 影响范围

预计涉及以下前端文件：

- `src/components/Settings/EngineSettingsPanel.tsx`
- `src/components/Settings/settingsOptions.ts`
- `src/components/Common/ConnectingOverlay.tsx`
- `src/utils/engineLabels.ts`

如有必要，允许少量触及与展示文案强绑定的辅助模块，但不扩展到后端。

## 验证标准

完成后需要满足：

1. 设置页可选择 `custom-cli`
2. 选中 `custom-cli` 后不显示路径输入 UI
3. 设置页中 `custom-cli` 仍可配置服务商与模型
4. 不再出现外部 CLI 的安装/查找/探测命令文案
5. 前端构建通过

## 后续阶段

后续如果要“提升 Agent 能力”，应另开独立设计，重点讨论：

- 运行模式
- 工具权限
- 自动执行策略
- 会话能力

这些内容不纳入本次实现。
